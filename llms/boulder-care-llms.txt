# Boulder Care

> Boulder Care is a Portland, Oregon telehealth provider founded in 2017 by Stephanie
> Strong, delivering evidence-based outpatient treatment for opioid and alcohol use
> disorder entirely through a mobile app. Participants connect to a collaborative care
> team — addiction medicine clinicians, peer recovery specialists and care coordinators —
> over secure video and messaging, and are prescribed medications for addiction treatment
> including buprenorphine/naloxone, naltrexone and acamprosate. The company focuses on
> Medicaid beneficiaries and other historically underserved populations and has served
> more than 12,000 participants. Boulder Care ships software only as an end-user patient
> product: there is no developer portal, no API documentation, no SDK and no
> machine-readable specification anywhere on its public surface. This file is generated
> by API Evangelist from public sources; it is not published by Boulder Care.

## API surface

- **None published.** Boulder Care markets no API. Its sitemap (156 URLs) contains no
  developer, docs, API or integration page, and `/developers`, `/developer`, `/api`,
  `/docs` and `/api-docs` all return HTTP 404.
- One real machine API exists and was found by probe, but is undocumented: an Apollo
  GraphQL server at the root of `https://api.boulder.care/`. It executes GraphQL for an
  unauthenticated caller (`{__typename}` returns `{"data":{"__typename":"Query"}}`), but
  **introspection is disabled** (`INTROSPECTION_DISABLED`), so no schema can be read. It
  is the backend for the Boulder Care patient mobile app, not a product API. No SDL was
  captured and none was invented.
- `app.boulder.care` is a Branch.io deep-link host for the mobile app. It answers HTTP
  200 with the same HTML interstitial for every path, including every `/.well-known/*`
  and spec path — those 200s are soft-404s, not documents.
